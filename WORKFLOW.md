## 1. 🧬 DEVELOPMENT LIFECYCLE

### A. Branching Strategy

Direct commits to `master` are **FORBIDDEN** (except for release commits generated by scripts).

**Format:** `type/kebab-case-description`

**Types:**

- `feat/` - New features (e.g., `feat/streaming-parser`)
- `fix/` - Bug fixes (e.g., `fix/worker-race-condition`)
- `refactor/` - Code changes without behavior change
- `chore/` - Config, scripts, deps (e.g., `chore/update-webpack`)
- `docs/` - Documentation only

**Command:** `git switch -c feat/streaming-parser-v1`

### B. The Coding Standard (Law)

1. **File Identity Headers (MANDATORY):**
   Every source file (.ts, .rs, .js, .ps1) MUST start with a relative path comment.
   _Why?_ Context preservation for AI & Debugging.
   _Auto-Fix:_ Run `pwsh ./scripts/add-headers.ps1` to automatically insert/update them.

2. **No console.log:**
   Use `logger.info()`, `logger.warn()`, or `logger.error()`.
   _Exception:_ Temporary local debugging, but must be removed before push.

3. **Strict Typing:**
    - `any` is banned. Use `unknown` + Type Guards.
    - Interfaces must be explicit.

4. **Error Handling:**
    - Never swallow errors.
    - Always use `normalizeUnknownError(e)` before logging.
    - UI must gracefully degrade (show toast/banner), never white-screen.

### C. The Dev Loop

- **Start Dev Server (Hot Reload):** `npm start`
- **Watch Rust Changes (Separate Terminal):**
    ```bash
    cd src/wasm-core
    cargo watch -s "wasm-pack build --target web --out-name index --dev"
    ```

## 2. 🛡️ THE GUARDIAN GATE (VERIFICATION)

The Guardian (`scripts/verify-all.js`) is the supreme authority. If it fails, your code does not exist.

- **LEVEL 1: Quick Verify (During Dev)**
  _Runs linting, formatting check, and fast compilation. Skips heavy tests._
  `npm run verify:all -- --fast --no-push`

- **LEVEL 2: Full Verify (Pre-Commit)**
  _Runs everything except the heaviest audit checks. Includes Unit Tests with coverage._
  `npm run verify:all -- --no-push`

- **LEVEL 3: Strict Verify (Pre-Push / Release)**
  _The complete battery of tests. This is what CI runs._
  `npm run verify:all:strict -- --no-push`

### Checklist executed by Guardian:

- [ ] **Header Check:** Are file paths present and correct?
- [ ] **Conflict Check:** Are there any `<<<<<<<` git markers?
- [ ] **Big File Gate:** Are there committed files > 5MB?
- [ ] **Security Sniffer:** Scans for secrets/keys in code.
- [ ] **I18n Integrity:** Are all keys in `sr.ts` present?
- [ ] **Rust Gates:** `cargo fmt` (check), `cargo clippy` (no warnings), `cargo test`.
- [ ] **Build Gate:** Does `npm run build` (Webpack prod) succeed?
- [ ] **Test Gate:** `vitest run --coverage` (Threshold: 80% global).
- [ ] **E2E Gate:** `playwright test` (Headless browser smoke tests).

## 4. 🚀 COMMIT, PUSH & PR

### Commit Protocol

We use **Conventional Commits**. This is required for the automated changelog generator.

- `feat: ...` -> Minor version bump (1.1.0)
- `fix: ...` -> Patch version bump (1.0.1)
- `BREAKING CHANGE: ...` -> Major version bump (2.0.0)

**Push Sequence:**

```bash
# 1. Final Check
npm run verify:all -- --no-push

# 2. Stage & Commit
git add .
git commit -m "feat: implement streaming xml parser with quick-xml"

# 3. Push
git push -u origin feat/streaming-parser
```

### Husky Hooks:

- `pre-commit`: Runs linter and conflict checks.
- `pre-push`: Runs TypeScript type-check and basic tests.
- _Bypass:_ Use `--no-verify` only in extreme emergencies (e.g., saving WIP).

## 5. 📦 RELEASE PROCEDURE (Maintainers Only)

Releases are automated via `standard-version`. Do not manually edit `package.json` version.

1. **Sync:** `git pull origin master`
2. **Verify:** `npm run verify:all:strict -- --no-push`
3. **Dry Run:** `npm run release -- --dry-run`
4. **Execute:** `npm run release` (bumps version, updates CHANGELOG.md, update manifests, commit, tag).
5. **Publish:** `git push --follow-tags` (triggers Cloudflare Pages deployment).

## 6. 🚑 TROUBLESHOOTING

- **Q: "WASM module not found" or "File not found" in Webpack?**
  A: You likely cleaned the project but didn't rebuild WASM. Run `npm run build:wasm`.

- **Q: "Office.js is not defined" in tests?**
  A: Ensure you are mocking Office global in your test setup (`tests/setup.ts`).

- **Q: "TextEncoder is not defined" in Worker tests?**
  A: Ensure `src/taskpane/worker/transliteration.worker.ts` has the polyfill import at the top.

- **Q: E2E Tests failing randomly?**
  A: Increase timeout in `playwright.config.ts`. Word Online can be slow to initialize the taskpane iframe.
